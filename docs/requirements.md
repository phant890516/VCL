## 1. はじめに

### 1.1 開発目的

本システムは、小学校高学年から中学生を主な対象とし、危険な試薬を実際に扱わずに化学実験の流れや反応の変化を体験できる学習用 Web アプリケーションである。

当初案では、3D プリントした実験器具型デバイスに ESP32 とセンサーを内蔵する構成を想定していた。しかし現行の実装では、専用ハードウェアではなく Nintendo Joy-Con を PC に Bluetooth 接続し、Joy-Con の傾き・ボタン・スティック入力を実験操作として利用するプロトタイプ方式を採用している。

この方式により、専用筐体の完成を待たずに、以下の体験を先行して検証できる。

#### 先行検証の対象

- 試験管やフラスコを傾ける操作の代替入力
- 試薬を注ぐ、振る、混ぜるといった実験操作のシミュレーション
- Three.js による 3D 実験室画面での反応表示
- 学習履歴やトロフィーによる継続的な学習支援

### 1.2 適用範囲

本書は、VCL の現行 Web アプリケーション、バックエンド API、SQLite データベース、Joy-Con 接続処理、3D 実験画面、学習補助機能を対象とする。

本バージョンでは、以下は対象外または将来拡張とする。

#### 対象外・将来拡張

- ESP32 を搭載した専用実験デバイス
- 3D プリント筐体の量産仕様
- 実試薬を用いた物理実験
- 教室全体を想定した本格的な同時接続管理

| --- | --- |

| Joy-Con | Nintendo Switch 用コントローラー。本実装では疑似実験器具の代替入力デバイスとして扱う。 |

## 2. システム概要

### 2.1 現行コンセプト

VCL は、PC 上で動作する Web アプリケーションと Joy-Con を連携させ、化学実験を疑似的に体験するシステムである。ユーザーは画面上の実験室で薬品を選び、Joy-Con を傾けたり振ったりすることで、試験管やフラスコに対する操作を行う。

実験結果は Three.js の 3D 表示に反映され、液体の色変化、泡、沈殿、溶解などの視覚的変化として表現される。

### 2.2 システムの流れ

#### 処理シーケンス

1. ユーザーが PC に Joy-Con を Bluetooth 接続する。
2. Node.js バックエンドが `node-hid` を用いて Joy-Con を検出する。
3. Joy-Con の加速度、ジャイロ、ボタン、スティック入力を解析する。
4. 解析結果を Socket.IO の `gyro-data` イベントとしてフロントエンドへ送信する。
5. フロントエンドは受信した角度や入力を 3D 実験室画面へ反映する。
6. 実験条件を満たした場合、反応表示と解説、トロフィー付与を行う。

### 2.3 技術スタック

| カテゴリ | 技術 |
| --- | --- |
| フロントエンド | Vite, JavaScript ES Modules, Three.js, Socket.IO Client |
| バックエンド | Node.js, Express, Socket.IO, node-hid |
| データベース | SQLite |
| テスト | Vitest, Playwright |
| 入力デバイス | Nintendo Joy-Con |
| 実行環境 | PC ブラウザ + ローカル Node.js サーバー |

### 2.4 アーキテクチャ

バックエンドは Controller、Service、Repository を分けた三層構成を基本とする。Joy-Con 連携は `JoyConService` が担当し、HID デバイスの検出、入力レポートの解析、キャリブレーション、イベント発行を行う。

フロントエンドは SPA として構成し、ルーターにより各画面を切り替える。3D 表示は `LabScene` を中心に行い、画面ごとの View が UI 操作と画面遷移を管理する。

## 3. 入力デバイス要件

### 3.1 Joy-Con 接続

| 項目 | 要件 |
| --- | --- |
| 接続方式 | PC の Bluetooth 機能で OS に Joy-Con をペアリングする。 |
| 検出方式 | バックエンドが `node-hid` で Joy-Con の Vendor ID / Product ID を検出する。 |
| 検出間隔 | 2 秒間隔でデバイス一覧をポーリングする。 |
| 対応デバイス | Joy-Con L、Joy-Con R。 |
| 割り当て | 1 台目を試験管、2 台目をフラスコとして扱う。実装上は検出順に依存する。 |
| 初期化 | Joy-Con を 0x30 入力レポートモードに設定し、センサー値を取得する。 |

### 3.2 入力データ

| 入力 | 用途 |
| --- | --- |
| 加速度 | 傾き角度の算出、注ぐ動作の検知。 |
| ジャイロ | 傾き角度の補正、動きの検知。 |
| ボタン | 周期表操作、選択、キャンセルなどの UI 操作に利用可能。 |
| スティック | 周期表上のカーソル移動に利用可能。 |

### 3.3 キャリブレーション

Joy-Con 接続後、一定サンプル数のジャイロ値を取得し、オフセットを算出する。キャリブレーション中は安静状態を想定し、完了後に角度計算を開始する。

現行実装では、角度の急激な飛びや微小な揺れを抑えるため、以下の補正を行う。

#### 補正・フィルタ

- ジャイロ値のデッドゾーン処理
- 加速度とジャイロを組み合わせた相補フィルタ
- 角度を概ね -120 度から 120 度の範囲へ制限
- フラスコ側の動きに対する平滑化

### 3.4 制約

#### 制約一覧

- Joy-Con はブラウザから直接接続せず、バックエンドの `node-hid` 経由で扱う。
- OS 側で Joy-Con の Bluetooth 接続が完了していない場合、アプリから自動ペアリングはできない。
- 検出順により試験管とフラスコの割り当てが変わる可能性がある。
- Joy-Con は本来実験器具ではないため、操作感は疑似的なものである。

## 4. 機能要件

### 4.1 画面一覧

画面ごとの詳細な表示内容、操作、保存処理、遷移は [VCL 画面仕様書](./screen_spec.md) に記載する。本書では主要画面の役割のみ定義する。

| 画面 | 概要 |
| --- | --- |
| ダッシュボード | アプリ起動後のホーム画面。 |
| 接続ガイド | Joy-Con の接続状態と角度を確認し、実験開始前の確認を行う。 |
| セレクトモード | 実装済み実験を一覧表示し、選択した実験を開始する。 |
| フリーモード | 自由に薬品を選び、3D 実験室で反応を試す。 |
| 実験室 | Three.js による 3D 実験画面。Joy-Con 入力を反映する。 |
| トロフィー | 獲得した実績を表示する。 |
| 設定 | 音量やテーマなどの設定を扱う。 |
| ログイン / 登録 | ユーザー登録とログインを行う。 |
| 管理者画面 | 管理用機能を扱う。 |
| Live / Idea | 発表・補助画面として利用する。 |

### 4.2 接続ガイド

接続ガイドでは、ユーザーが Joy-Con を接続できているかを確認する。

#### 要件

- バックエンドとの Socket.IO 接続状態を表示する。
- Joy-Con から `gyro-data` が届いた場合、接続完了として表示する。
- 角度値をリアルタイムに表示する。
- 3D Joy-Con 表示を角度に合わせて回転させる。
- 一定以上の角度変化を検知した場合、動作確認完了とする。

### 4.3 セレクトモード

セレクトモードでは、実装済みの実験をカード形式で表示する。利用可能な実験のみ開始ボタンを有効にし、未実装の実験は Coming Soon として表示する。

実験カードの表示内容は `frontend/src/data/quests.js` のクエスト定義を参照する。これにより、タイトル、説明、使用物質、利用可否、カード背景をコード内の画面処理から分離する。

### 4.4 実験室

実験室では、試験管、フラスコ、液体、薬品などを 3D 表示する。Joy-Con 入力により、傾ける、注ぐ、振る、混ぜるなどの操作を疑似的に行う。

#### 要件

- Joy-Con の角度を試験管またはフラスコの回転に反映する。
- 指定角度以上の傾きで注ぐ動作を扱う。
- 振る動作または角度変化の蓄積により混合進行度を更新する。
- 実験条件を満たした場合、成功演出と解説ダイアログを表示する。
- 実験成功時に対応するトロフィーを保存する。
- クエスト定義の `scene` と `reaction.effects` に基づき、泡、白濁、沈殿、固体の溶解、色変化などの共通演出を制御する。

### 4.5 クエスト定義方式

バックエンドを理解していないメンバーでも実験内容を追加・編集しやすくするため、実験ごとの情報は `frontend/src/data/quests.js` に集約する。

#### クエスト定義に含める主な項目

- 実験 ID、タイトル、説明、使用物質、利用可否。
- セレクトモード用の表示情報。
- 実験室で表示するミッション文。
- 実験開始時のフラスコ内状態。
- ツールバーに表示する薬品投入ボタン。
- 反応に必要な投入物の名称。
- 混合完了に必要な進行度。
- 色変化、泡、沈殿、固体の溶解などの演出指定。
- 成功時の解説文、反応式、トロフィー ID。

#### ID 命名規則

- 実験 ID は `exp_01` のように、内容名を含めず番号のみで管理する。
- トロフィー ID は `trophy_exp_01` のように、対応する実験 ID と同じ番号を使う。
- 実験名や表示文を変更しても、ID は原則として変更しない。

#### 現行対象

現行のクエスト定義方式は、薬品を投入し、Joy-Con でフラスコを振って混ぜることで成立する実験を対象とする。加熱、燃焼、炎色反応、蒸発など、熱源や炎の操作が必要な実験は本バージョンでは対象外とする。

この方式により、クエスト担当者は `quests.js` を編集するだけで、同じ形式の「薬品を入れる」「振って混ぜる」「色が変わる」「泡や沈殿が出る」タイプの実験を追加できる。

クエスト定義の具体的な書き方は [VCL クエスト追加マニュアル](./quest_manual.md) に記載する。

### 4.6 周期表・薬品選択

フリーモードでは周期表を表示し、選択した元素または薬品を試験管・フラスコに投入できる。

#### 要件

- 周期表から物質を選択できる。
- 物質の詳細情報を表示できる。
- マウス操作に加え、Joy-Con のスティックまたは方向ボタンで選択移動できる。
- 選択した物質を試験管またはフラスコへ設定できる。

### 4.7 トロフィー

実験成功や特定条件の達成に応じてトロフィーを付与する。

現行実装では、トロフィー獲得状態はブラウザの LocalStorage に保存する。バックエンド側にもトロフィー用 API と DB テーブルは存在するが、現行フロントエンドではローカル保存を優先する。

## 5. ユーザー機能

### 5.1 アカウント登録

ユーザーはニックネーム、メールアドレス、パスワードを登録できる。バックエンドでは bcrypt によるパスワードハッシュ化を行う。

Supabase 運用では、先生のみ Supabase Auth のメールアドレス認証を利用する。生徒はメールアドレスを持たない前提とし、先生がクラス単位で生徒 ID と初期パスワードを発行する。

### 5.2 ログイン

ユーザーはメールアドレスまたはユーザー情報を用いてログインする。ログイン成功時はユーザー情報を保存し、アプリ内画面へ遷移する。

現行実装では、学校運用を想定した二段階認証やアカウントロックは未実装または将来拡張とする。

Supabase 運用でのログイン種別は以下とする。

| 種別 | 認証方式 | 保存 |
| --- | --- | --- |
| 先生 | Supabase Auth のメール + パスワード。メール認証済みのみクラス管理を許可する。 | Supabase |
| 生徒 | 先生が発行した生徒 ID + 初期パスワード。初回ログイン後にパスワード変更を求める。 | Supabase |
| ゲスト | ログインなし。 | 保存なし |

### 5.3 設定

設定画面では、アプリ内の表示や音量など、ユーザー体験に関わる項目を変更できる。

### 5.4 学習履歴

トロフィー画面により、ユーザーの達成状況を確認できる。実験ごとの詳細なポートフォリオ機能は将来拡張とする。

### 5.5 データベース保存方針

DB のテーブル定義、保存先の使い分け、インデックス、API 対応、Supabase RLS 方針は [VCL データベース設計書](./database_design.md) に記載する。

本書では以下の方針のみ定義する。

- ローカル開発・デモでは SQLite を使用する。
- 学校運用では Supabase を使用し、先生・クラス・生徒・進捗・トロフィーを管理する。
- ゲスト利用または通信失敗時のみ LocalStorage を補助保存先として扱う。
- パスワードは平文保存せず、ハッシュ化して保存する。

### 5.6 学習進捗 API

ログインユーザーが実験を完了した場合、実験コード、進捗状態、必要に応じて混合量を保存する。SQLite 用 API と Supabase 学校運用 API の詳細は [VCL データベース設計書](./database_design.md) に記載する。

### 5.7 トロフィー保存方針

トロフィーは、ログインユーザーでは DB を正とする。未ログインまたは通信失敗時のみ LocalStorage に保存し、次回ログイン時に未同期データを DB へ同期する。

### 5.8 Supabase 学校運用スキーマ

Supabase では `supabase/schema.sql` を適用し、先生・クラス・生徒・進捗・トロフィーを管理する。テーブル構造、進捗状態、API、RLS 方針は [VCL データベース設計書](./database_design.md) に記載する。

## 7. 非機能要件

### 7.1 操作性

#### 目標

- 初回利用者でも Joy-Con 接続状況が分かる接続ガイドを用意する。
- 実験中の UI はマウス操作と Joy-Con 操作の両方に対応する。
- 角度や混合進行度をデバッグ表示できることが望ましい。

### 7.2 安定性

#### 目標

- Joy-Con が未接続でもアプリ全体は起動できる。
- Joy-Con 接続エラーはバックエンド起動失敗に直結させず、任意機能として扱う。
- デバイス切断時は再接続待機状態に戻る。

### 7.3 保守性

#### 目標

- 実験データは `frontend/src/data/experiments.js` のようなデータ定義に集約する。
- Joy-Con 解析処理は `backend/src/services/joyconService.js` に集約する。
- 実験ごとの反応ロジックは 3D 表示処理と過度に混在させず、拡張しやすい単位に分ける。

### 7.4 セキュリティ

#### 目標

- パスワードは平文保存せず、ハッシュ化して保存する。
- API は必要に応じて認証トークンによる保護を行う。
- 画像アップロードなど、不要なファイル入力機能は搭載しない。

## 8. エラーハンドリング

| エラー | 条件 | 表示・挙動 |
| --- | --- | --- |
| Joy-Con 未接続 | `gyro-data` が届かない | 接続ガイドで接続待機状態を表示する。 |
| Joy-Con 切断 | HID エラーまたはデバイス close | バックエンドで接続情報を削除し、再検出を待つ。 |
| バックエンド未起動 | Socket.IO 接続不可 | フロント側で接続不可状態として扱う。 |
| センサー値の揺れ | 微小な角度変化が続く | デッドゾーンと平滑化により過剰反応を抑える。 |
| 実験条件未達 | 注ぐ、混ぜるなどの条件不足 | 成功扱いにせず、反応進行を待つ。 |

## 9. ハードウェア構成とコスト

現行プロトタイプでは、専用 ESP32 デバイスではなく Joy-Con を入力デバイスとして使用する。

| 部品 | 数量 | 備考 |
| --- | --- | --- |
| PC | 1 | Node.js サーバーとブラウザを実行する。 |
| Joy-Con L / R | 1 組 | 試験管・フラスコ操作に使用する。 |
| Bluetooth アダプタ | 必要に応じて 1 | PC に Bluetooth がない場合に使用する。 |

専用ハードウェア案は将来拡張として残すが、現行の開発・発表・検証では Joy-Con 方式を正式な対象とする。
