## 1. 目的

この文書は、VCL の画面ごとの役割、表示内容、操作、保存処理を整理するための画面仕様書である。

画面遷移は `frontend/src/main.js` と `frontend/src/router.js` で管理する。各画面は `frontend/src/views` 配下に配置する。

## 2. 共通仕様

### 2.1 画面構成

- SPA として動作し、History API により URL と表示画面を同期する。
- サイドバーから主要画面へ遷移できる。
- サイドバーには「ホーム」「クエスト」「ログイン」「ひらめき」「トロフィー」を表示する。
- 画面本体は `#content-root` に描画する。
- ログイン、登録、404 などの補助画面も共通サイドバー配下で表示し、画面全体を覆ってサイドバーを隠さない。
- Joy-Con 入力はバックエンドの Socket.IO から `gyro-data` として受け取る。
- 画面HTMLは `template.html` や `*.template.html` に分離し、JSに長いHTML文字列を直書きしない。
- 動的なカードやセルはHTML側の `<template>` を複製し、JSではテキストや属性だけを差し込む。

### 2.2 保存先

| 情報 | 保存先 |
| --- | --- |
| 通常ユーザー情報 | LocalStorage の `vcl_user` / `vcl_token` |
| 学校運用の先生トークン | LocalStorage の `vcl_teacher_access_token` |
| 学校運用の生徒トークン | LocalStorage の `vcl_student_token` |
| ゲストまたは通信失敗時のトロフィー | LocalStorage の `vcl_user_trophies_offline` |
| 生徒ログインユーザーの進捗・トロフィー | Supabase |
| 通常ログインユーザーの進捗・トロフィー | 未実装。共同実装でDB方針を決める |

## 5. 登録画面

| 項目 | 内容 |
| --- | --- |
| 目的 | ユーザーアカウントを作成する |
| 入力 | ユーザー名、メールアドレス、パスワード、ロール |
| API | `POST /api/auth/register` |
| 保存 | 成功時に `vcl_token` と `vcl_user` を LocalStorage へ保存 |
| 遷移 | 登録成功後にダッシュボードへ遷移 |

先生ロールを選択できるが、学校運用の正式な先生認証は Supabase Auth を利用する。

## 6. ログイン画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 既存ユーザーとしてログインする |
| 入力 | メールアドレスまたはユーザー名、パスワード |
| API | `POST /api/auth/login` |
| 保存 | 成功時に `vcl_token` と `vcl_user` を LocalStorage へ保存 |
| 遷移 | ログイン成功後にダッシュボードへ遷移 |
| 導線 | サイドバーの「ログイン」から `/login` へ遷移 |
| 表示 | 左側にラボ端末風のステータス表示、右側にログインフォームを配置し、サイドバー配下の表示幅でも横長に崩れないようにする |

## 7. 接続ガイド

| 項目 | 内容 |
| --- | --- |
| 目的 | Joy-Con の接続状態を確認する |
| 入力 | Socket.IO の `gyro-data` |
| 主な表示 | バックエンド接続状態、Joy-Con 角度、3D Joy-Con |

| エラー | バックエンド未起動または Joy-Con 未接続の場合は待機表示 |

## 9. 実験室

| 項目 | 内容 |
| --- | --- |
| 目的 | 3D 空間で実験操作を行う |
| データ | `quests.js`、周期表データ、Socket.IO の Joy-Con 入力 |
| 主な表示 | 試験管、フラスコ、液体、固体、ツールバー、ミッション文 |
| 主な操作 | 薬品選択、注ぐ、振る、混ぜる、周期表選択 |
| 成功時 | 解説ダイアログ表示、進捗保存、トロフィー保存 |

### 9.1 セレクト実験

- `params.id` の実験 ID をもとに `quests.js` からクエストを取得する。
- `mission` を実験中の指示として表示する。
- `toolbarActions` から薬品投入ボタンを生成する。
- `reaction` の条件を満たしたら成功扱いにする。

### 9.2 フリーモード

- `/free-mode` から入った場合は、タイトルを「フリー実験」とする。
- 周期表から物質を選び、試験管またはフラスコへ設定できる。
- 成功判定やトロフィー付与は、クエスト指定がある場合を優先する。

### 9.3 保存処理

| タイミング | 保存内容 | 保存先 |
| --- | --- | --- |
| 実験成功 | `completed` 進捗 | 生徒ログイン時は `/api/school/students/progress` |
| 実験成功 | トロフィー ID | 生徒ログイン時は `/api/school/students/trophies` |
| 通常ログイン時 | 進捗・トロフィー | 未実装。共同実装でDB方針を決める |
| 通信失敗 | トロフィー ID | LocalStorage |
